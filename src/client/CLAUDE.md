# src/client — browser

Applies together with the root `CLAUDE.md`. **Web on PC first; phone and tablet are also a priority** (Fernando, Nov 16, after the tablet could not be played): follow the touch rules in the design system, section 8.

## Who owns what

- `entry.ts`: what `index.html` loads; opens the town or builds the battle, its scene and its `Game`.
- `main.ts` (`Game`): wires everything; owns the turn loop. `hero-turn.ts` (`HeroTurn`) owns the turn screen (screen, Ui and cursor) and `battle-input.ts` the listeners.
- `game/`: what opens around the battle: URL boot (`boot.ts`, `selectBattle`), title (`title.ts`), Options (`options.ts`), end windows (`end-screens.ts`), save slots window (`saves-ui.ts`), walkable town (`town.ts`, rules in `town-map.ts`), town menu, gate and expedition (`crawl.ts`).
- `command.ts`: what the menu shows and what comes next. `interaction.ts`: what the chosen tile does. Both pure and tested.
- `scene.ts` (`BattleScene`): only draws, composing `scene/` (`Board`, `Marks`, `Units`, `CameraRig`, `TileSpace`, `Timeline`), each built from what it needs.
- `hud.ts` (`BattleHud`): only shows and passes clicks along.
- `touch-input.ts` (`TouchInput`) only translates gestures and mouse; `keyboard.ts` and `gamepad.ts` translate keys and buttons into actions (pure, tested).
- `group.ts`, `chest.ts`, `saves.ts`, `store.ts`: party, gold and items, save slots, storage.
- A class holding a resource (WebGL, listeners) has `dispose()`.

## Rules

- **Logic that can be pure is pure and tested** (`command.ts`, `interaction.ts`, `turn-marks.ts`, `turn-list.ts`, `charge-lines.ts`, `battle-face.ts`, `tally.ts`, `town-map.ts`, `group.ts`, `saves.ts`, `glass.ts`, `ui3d/spring.ts`, `ui3d/layout.ts`, `ui3d/skin-flags.ts`, `menu3d/menu-view.ts`); the DOM and Three.js files only show it.
- **Interface follows the [design system](../../docs/game-design/design-system.md).** Change a token or a piece, change that document in the same commit. Colours and sizes only through the `:root` variables. A new HUD piece is a `.panel` with `.item` rows (`.focus` marks the focus), `gauge()` and `unitPanel()` from `hud-pieces.ts`. A new blue surface paints the `--glass*` stops over `--panel-veil` and joins the `backdrop-filter` list in `style.css`, so the panel opacity and blur (`glass.ts`, `dt:glass`) reach it; never `--paper*` for a panel background. Focus outside the panels takes `--focus-halo`; a disabled button says why in its text.
- **DOM through the pieces** of `icons.ts` (`el`, `icon`, `button` for every text button, `iconButton`) and `dialog.ts` (`dialog()`, `choice()`, `slider()`). Inline `style` only for positions and sizes computed at run time. Colour is never the only signal.
- **Text the player sees:** `t('pt', 'en')` from `i18n.ts`; names via `unitName`/`abilityName`. An action's result also as text (`eventLog`, in the help line), not only the floating number.
- **Input:** keyboard, mouse and gamepad move the same cursor and go through `Game.runKey` (in the town, `Town.run`). A new key or button goes into `keyAction` or `padActions`, the `ACTIONS` table of `glyphs.ts` (action, key, pad button; `tests/glyphs.test.ts` checks it against both), the `keyHelp` list and a `hint(action)` in the HUD. No key or button name is written by hand: a hint is `hint(action)`, a 3D cap `capMeshes` (`ui3d/caps.ts`), a line of text `hintLine` or `keysText`, so all follow the input in use (`key-hints.ts`: Options › Key icons, `dt:glyphs`; an action with no pad button hides its hint). No keyboard `if` in the scene or the HUD.
- **Timing:** every wait and animation in battle runs on the battle clock (`BattleScene.wait`, `Timeline.animate`), so the speed-up applies. No `setTimeout` for battle timing. Flow timings live in `timing.ts`, gestures in `fx.ts`, sound in `sound.ts`.
- **Randomness:** `Math.random` only picks a new seed (`newBattle`, `startExpedition`) or drives cosmetics (town strolls, water, sound, confetti); every roll inside a battle goes through the rules' RNG.
- **Storage:** preferences and saves go through `store.ts` with the `dt:` prefix. A change of key or format goes into `MIGRATIONS` (runs once per browser, counted in `dt:migrated`), so nobody loses progress. A new progress key joins `PROGRESS_KEYS` (`saves.ts`) so it travels with its save slot. Every save read back is rebuilt by its `parse*` function.
- **Half tiles:** every battle the client opens is halved (`selectBattle`). Any screen that shows Move or Jump shows the half-tile number the game spends (sheet value x `SUB`).
- **Interface places and looks (Fernando, Nov 16):** a piece of the battle interface sits on its region of `ui3d/layout.ts` (FFT The Ivalice Chronicles at 1920x1080) through `stage()` and `place()`, or `--lay-u`, `--lay-x`, `--lay-y` in CSS, never on a corner of its own, so both layouts (`edges`, `frame`; `layout-mode.ts`, `dt:layout`) reach it. Its look is read only in `ui3d/skin-flags.ts`: a new piece or look joins `PIECES` and `scripts/sandbox/bench/ui-pecas.json`, no new `param()` flag elsewhere.
- **3D interface (localhost flags `?menu=3d`, `?turn=3d`, `?bar=3d`, `?banner=3d`, `?height=3d`, `?hints=3d`, `?confirm=3d`, `?result=3d`, `?party=3d`, `?shop=3d`, `?townhud=3d`, `?townmenu=3d`, `?talk=3d`, `?options=3d`, `?title=3d`, `?tools=3d`, `?status=3d`, `?map=3d`, `?ui=3d`; Fernando, Nov 16):** one shared WebGL layer (`ui3d/layer.ts`), never a second canvas or context, and no glass blur. A 3D screen is a thin `Ui3dScreen` built from the kit in `ui3d/` (panel, text, icons, pixel filter, spring); what it shows and where is pure and tested (`menu-view.ts`, `menu-layout.ts`, `queue-view.ts`), with no Three.js or DOM. It brings its own input (transparent buttons from the same layout it draws) and needs no screen reader path; it keeps the game's accessibility: the `--ui3d-*` tokens' contrast, 16 px text, Reduce motion (`layer.still`), keys and gamepad. Motion is springs on the battle clock; draw only while something moves. A full screen with form controls (Options, the title; `flow3d/`) keeps its HTML window unseen under the drawing, sized by the same pure layout, so every input and the screen reader stay the window's; a page under `fits` (1152x648) keeps the HTML one. The expedition map (`town3d/map3d.ts`, hook `setMap3d` in `game/expedition-map.ts`) does the same over its `dialog()` window, with the places' buttons seated under the drawn seals. **Arrows and d-pad follow the screen (Fernando, Nov 17):** in a 3D screen a direction goes to the nearest item straight that way (lay the items out in rows and columns) and stays put at an edge, never by list order and never on a slant; a window of scattered buttons takes the `.spot-walk` class and `dialog.ts` walks it with the pure `nextSpot` (`spot-walk.ts`, tested), an `.arrow-walk` group the same way; a screen over a window takes the `walk` event (`dialog.ts` `walked`) and a town window `byPlace`, both through `neighbour` (`ui3d/walk.ts`) over pure boxes with a test per direction and per edge. The pad's d-pad is the arrow it stands for: it never walks a window sideways by list order. Outside `ui3d/`, `menu3d/`, `turn3d/`, `bar3d/`, `hints3d/`, `confirm3d/`, `result3d/`, `town3d/`, `flow3d/` and `window3d/` the 3D code is named only by `import type` or a dynamic import in `hud-skin.ts` (the pure `ui3d/layout.ts` and `ui3d/skin-flags.ts` excepted), so the game online never fetches it (`tests/ui3d.test.ts`). The town's windows (`town3d/`, loaded by `loadTownSkin`) are one screen fed by pure pages (`page.ts`: things to draw and buttons in reference px), over a `dialog()` window with real unseen buttons; the openers hand over through `town3d` in `town-ui.ts` and keep the HTML window when there is no WebGL, the context is lost or the page is under `MIN_SCALE`. The town's HUD (`hud3d.ts`) and speech box (`talk3d.ts`) are drawn over their HTML pieces, unseen by `opacity` (never `visibility`: they stay the layout and the input).
- **Pieces by name (Fernando, Nov 18: the whole interface becomes 3D):** a screen joins the 3D layer with the name of its piece, `layer.add(screen, name)`, from `PIECE_NAMES` (`ui-pieces.ts`; `null` only for a screen of several pieces, which reads `pieceHidden` for each). The sandbox's `hide` and the drawing guides (`?guides=1`, `ui3d/guides.ts`, a screen like the others) go by that name, never by a selector of an HTML panel; the layer hears a layout change itself (`onLayout`, `layout-mode.ts`).
- **Automation:** on `localhost` the music starts at 0, and under automation (`navigator.webdriver`) it never plays unless the URL has `?music=1`. Launch Chrome with `--mute-audio`.
